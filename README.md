# 🎁 ほしいものクイズ

母の還暦（60歳）のプレゼントを決めるための、アキネーター風の質問アプリです。

「お菓子でいいよ」と言われてしまうけれど、遠方でなかなか会えず好みもよくわからない。
それなら本人に2択・3択をポチポチ押してもらって、
その答えから欲しいものを当てにいこう、という趣旨のものです。

- 質問は **8〜11問**。答えに応じて次の質問が変わります
- **押すたびに、その時点の答えが自動で送られます**。母が「送信」を押す必要はありません
- 途中でやめられても、そこまでの答えは残ります
- 最後に候補が3つ出て、本人が1つ選び、ひとことを添えられます
- 見た目は還暦の赤。文字も押すところも大きめにしてあります

## 全体の流れ

```
母のスマホ                    Google Apps Script          あなた
  ├ 選択肢を押す  ──────────▶  スプレッドシートに1行
  ├ 選択肢を押す  ──────────▶  同じ行を上書き
  ├ …                          （セッションごとに1行）
  └ 候補を1つ選ぶ ──────────▶  上書き＋メール通知  ─────▶ 📧
```

1行が1回ぶんの回答です。押すたびに同じ行が最新の状態に書き換わるので、
シートが途中経過で埋まることはありません。

## 公開のしかた（GitHub Pages）

1. GitHub のリポジトリ → **Settings** → **Pages**
2. **Source** を `Deploy from a branch` にする
3. Branch に公開したいブランチ（`main` など）、フォルダは `/ (root)` を選んで **Save**
4. 数分待つと `https://<ユーザー名>.github.io/happy-birthday-gift/` で開けます

GitHub Actions で公開したい場合は `.github/workflows/pages.yml` を用意してあります。
Settings → Pages の **Source** を `GitHub Actions` にすると、`main` への push で自動的に公開されます。
別のブランチを試しに公開したいときは、Actions タブから **Deploy to GitHub Pages** を
手動実行（Run workflow）してください。

## 自動送信の設定

回答の受け口として Google スプレッドシートを使います。無料で、サーバーを借りる必要がありません。

1. [Google スプレッドシート](https://sheets.new)で新しいシートを1つ作る
2. メニューの **拡張機能 → Apps Script** を開く
3. 出てきたエディタの中身を全部消して、`tools/apps-script.gs` の中身を貼りつける
4. 先頭のほうにある `NOTIFY_EMAIL` に、自分のメールアドレスを書く
   （空のままにするとメール通知はなく、シートに貯まるだけになります）
5. 右上の **デプロイ → 新しいデプロイ** → 種類は **ウェブアプリ**
   - 次のユーザーとして実行： **自分**
   - アクセスできるユーザー： **全員**  ← ここが「全員」でないと母の端末から送れません
6. 表示された **ウェブアプリのURL**（`https://script.google.com/macros/s/..../exec`）をコピー
7. `assets/config.js` を開いて貼りつける

   ```js
   const REPORT_ENDPOINT = 'https://script.google.com/macros/s/..../exec';
   ```

8. コミットして push。GitHub Pages に反映されれば設定完了です

うまくいったかどうかは、ウェブアプリのURLをブラウザでそのまま開くと確かめられます。
「ほしいものクイズの受け口は動いています」と出れば、受け口は生きています。

`REPORT_ENDPOINT` が空のままでも、アプリは普通に動きます。
その場合だけ、最後に本人が「LINEで送る」を押す方式に自動で切り替わります。

## しくみ

プレゼント候補にはそれぞれ「タグ」がついています（`sweets`, `appliance`, `together` など）。

1. 質問に答えるたびに、選択肢が持つタグの点数が加算される
   （マイナスの点数もあります。「服は自分で選びたい」なら `fashion: -3`）
2. プレゼントの点数 = そのプレゼントが持つタグの点数の合計
   ÷ √(タグの数)（タグが多い候補が有利になりすぎないようにするため）
3. **次の質問は、いまの上位候補の点差がいちばん大きく開く質問を選ぶ**

3番目がアキネーター的なところで、「答えを聞いたときにいちばん情報が増える質問」を
毎回えらび直しています。だから食べもの寄りの人には食べものを絞る質問が、
体験寄りの人には出かけ先の質問が飛んでくる、という動きになります。

8問を過ぎた時点で1位と2位が十分離れていたら、そこで打ち切ります（最大11問）。

### 送信のしかた

送り先は、使える順に自動で決まります。

1. Claude の Artifact 上で開いたときは、その `db`（動作確認用）
2. `assets/config.js` の `REPORT_ENDPOINT`（本番はこちら）
3. どちらも無ければ、最後に本人が「LINEで送る」を押す方式

毎回「その時点の回答ぜんぶ」を送っています。順番が前後して届いても、
最後の1通さえ正しければ結果が合うようにするためです。
送信中にもう一度押された分は、最新のものだけ残してまとめます。
電波が切れていたら、次に押したときにまとめて送り直します。

### 内容を変えるには

`assets/data.js` だけ触れば変えられます。

```js
// プレゼントを足す
{ id: 'my_gift', emoji: '🎁', name: '贈りたいもの',
  budget: '1万円くらい',
  note: '結果画面に出る説明文',
  tags: ['food', 'consumable', 'budget_low'] },

// 質問を足す
{ id: 'q_new', text: '聞きたいこと',
  choices: [
    { emoji: '🅰️', label: '選択肢A', tags: { food: 3, keepsake: -2 } },
    { emoji: '🅱️', label: '選択肢B', tags: { experience: 3 } }
  ] },
```

タグは新しく作っても構いません。結果画面に日本語で出したいときは、
`data.js` の先頭の `TAG_LABELS` に追加してください。

## プライバシー

- 送り先は `assets/config.js` に書いた自分のスプレッドシートだけです
- 途中まで答えた内容は端末の `localStorage` にも保存され、「前回のつづきから」で再開できます
- 「押すたびに息子に届く」ことは、最初の画面に書いてあります（黙って送ってはいません）

## 動作確認

4通りの回答パターン（お菓子派・体験派・実用家電派・家族派）で最後まで答えてみて、
妥当な候補が出ること・押すたびに自動送信されること・送信先が未設定なら手動送信に
戻ることを確かめるテストがあります。

```bash
npm install -D playwright && npx playwright install chromium   # 初回のみ
node test/e2e.mjs
```
