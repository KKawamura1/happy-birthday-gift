# 🎁 ほしいものクイズ

母の還暦（60歳）のプレゼントを決めるための、アキネーター風の質問アプリです。

「お菓子でいいよ」と言われてしまうけれど、遠方でなかなか会えず好みもよくわからない。
それなら本人に2択・3択をポチポチ押してもらって、
その答えから欲しいものを当てにいこう、という趣旨のものです。

- 質問は **9〜13問**。答えに応じて次の質問が変わります
- 候補を1つ選んだあと、**さらに1〜2問たずねて具体的な品まで絞ります**
  （「果物」→「桃」→「やわらかい白桃」、「大きな家電」→「洗濯機」→「ドラム式」）
- **迷った跡もすべて残します**。もどったところ、一覧で見送った候補、
  選びなおしたところまで、押した順にそのまま
- **金額はどこにも出しません**。値段が見えると遠慮が入り、
  「本当に欲しいもの」ではなく「安いもの」が選ばれてしまうためです
- **押すたびに、その時点の答えが自動で送られます**。母が「送信」を押す必要はありません
- 途中でやめられても、そこまでの答えは残ります
- 最後にひとことを添えられます
- 見た目は還暦の赤。文字も押すところも大きめにしてあります

## 全体の流れ

```
母のスマホ                          Google Apps Script        あなた
  ├ 選択肢を押す      ──────────▶  スプレッドシートに1行
  ├ 選択肢を押す      ──────────▶  同じ行を上書き
  ├ …（9〜13問）                    （セッションごとに1行）
  ├ もどって選びなおす ─────────▶  上書き（もどった跡も残る）
  ├ 候補を3つから1つ選ぶ ────────▶  上書き（見送った候補も残る）
  ├ 深掘り1問目       ──────────▶  上書き
  └ 深掘り2問目       ──────────▶  上書き＋メール通知  ─────▶ 📧
                                    （具体的な品名＋迷った跡つき）
```

1行が1回ぶんの回答です。押すたびに同じ行が最新の状態に書き換わるので、
シートが途中経過で埋まることはありません。

## 公開のしかた（GitHub Pages）

自動送信を使うので、**GitHub Actions 方式**で公開します
（送信先のURLを git に置かず、公開時に差しこむため）。

1. GitHub のリポジトリ → **Settings** → **Pages**
2. **Source** を `GitHub Actions` にする
3. `main` に push すると `.github/workflows/pages.yml` が動き、
   `https://<ユーザー名>.github.io/happy-birthday-gift/` で開けるようになります

別のブランチを試しに公開したいときは、Actions タブから
**Deploy to GitHub Pages** を手動実行（Run workflow）してください。

`Deploy from a branch` でも公開はできますが、その方式だと送信先の設定が
差しこまれないので、自動送信は無効（手動送信に切り替わり）になります。

## 自動送信の設定

回答の受け口として Google スプレッドシートを使います。無料で、サーバーを借りる必要がありません。

### 1. 受け口をつくる

1. [Google スプレッドシート](https://sheets.new)で新しいシートを1つ作る
2. メニューの **拡張機能 → Apps Script** を開く
3. エディタの中身を全部消して、`tools/apps-script.gs` の中身を貼りつける
4. 先頭のほうの3つを埋める
   - `SHARED_TOKEN` … 好きな文字列（合言葉）。あとで GitHub 側にも同じものを入れます
   - `NOTIFY_EMAIL` … 自分のメールアドレス。空ならシートに貯まるだけになります
5. 右上の **デプロイ → 新しいデプロイ** → 種類は **ウェブアプリ**
   - 次のユーザーとして実行： **自分**
   - アクセスできるユーザー： **全員**  ← ここが「全員」でないと母の端末から送れません
6. 表示された **ウェブアプリのURL**（`https://script.google.com/macros/s/..../exec`）をひかえる

URLをブラウザでそのまま開いて「ほしいものクイズの受け口は動いています」と出れば、受け口は生きています。

### 2. URLを GitHub Secrets に入れる

**URL と合言葉はリポジトリに書かないでください。** `assets/config.js` は `.gitignore` で
除外してあり、公開時に GitHub Actions が Secrets から組み立てます。

1. リポジトリの **Settings → Secrets and variables → Actions → New repository secret**
2. `REPORT_ENDPOINT` … さきほどのウェブアプリのURL
3. `REPORT_TOKEN` … Apps Script に書いた `SHARED_TOKEN` と同じ文字列
4. **Settings → Pages → Source** を `GitHub Actions` にする

以降、`main` に push すると公開され、そのときだけ config.js が組み立てられます。

手元で動かすときは、ひな型をコピーして使ってください（コピー先は git に入りません）。

```bash
cp assets/config.example.js assets/config.js
```

`REPORT_ENDPOINT` が空のままでも、アプリは普通に動きます。
その場合だけ、最後に本人が「LINEで送る」を押す方式に自動で切り替わります。

### 列の構成が変わったとき

`answers` シートの列は、機能を足すと変わることがあります。
そのときは**古いシートを `answers_old_日時` という名前に変えて残したうえで、
新しいシートを自動で作り直します**。手で直す必要はありませんし、古いデータも消えません。

## セキュリティについて

**このURLは秘密にできません。** クライアントだけで動く静的サイトなので、
公開ページのソースを見れば誰でも読めます。リポジトリが public かどうかは主因ではなく、
ページを公開した時点で受け口も公開されます。Secrets に置くのは、
**git の履歴に残さない**ため・**すぐ差し替えられる**ようにするためです。

### このURLで何ができて、何ができないか

| | |
| --- | --- |
| ❌ できない | シートを読むこと（`doGet` は固定の文字列を返すだけ） |
| ❌ できない | Google アカウントの他のデータに触れること（動くのは `doPost`/`doGet` だけ） |
| ❌ できない | 母の回答を書き換えること（セッションIDはランダムなUUIDで、当てられません） |
| ⚠️ できる | 知らない人がシートに行を足すこと |
| ⚠️ できる | あなた宛にメールを飛ばすこと |

⚠️ のほうは `tools/apps-script.gs` 側で抑えてあります。

- 合言葉が合わないPOSTは捨てる（通りすがりの機械よけ。認証ではありません）
- 本文の長さ・項目の長さ・配列の個数を、すべて上限で切る
- 1回答者あたり60回/15分、全体で600回/時 を超えたら受け取らない
- 新しく作れる行数は300まで。それ以上は増やせない
- `=` `+` `-` `@` で始まる文字列を無害化する
  （これを抜かすと `=IMPORTXML(...)` のような文字列がシート上で**数式として実行されます**）
- メールは1日20通まで。本文も切り詰め、注意書きを添える
- 何を弾いたかは返さない

これらは `test/apps-script.test.mjs` で、実際に敵対的なデータを投げて確認しています。

### 気になる場合の選択肢

- **専用の Google アカウントを作る** … 母の回答しか入らないアカウントにすれば、
  何かあっても他に影響しません
- **リポジトリを private に戻す** … GitHub Pages を private リポジトリから公開するには
  有料プラン（Pro 以上）が必要です。無料プランなら public にする必要があります
- **おかしなデータが入ったら** … Apps Script のデプロイを削除すればURLは即座に死にます。
  作り直して Secrets を差し替えてください。母には新しいURLを送り直す必要はありません
  （ページのURLは変わらないため）

## しくみ

プレゼント候補にはそれぞれ「タグ」がついています（`sweets`, `appliance`, `together` など）。

1. 質問に答えるたびに、選択肢が持つタグの点数が加算される
   （マイナスの点数もあります。「服は自分で選びたい」なら `fashion: -3`）
2. 集まった点を、**そのタグが集めうる最大点で割る**。
   「おうち時間」のように多くの質問から加点されるタグが、「甘いもの好き」のように
   一問しか出ないタグを押しつぶしてしまうのを防ぐため
3. プレゼントの点数 = そのプレゼントが持つタグの点数の合計
   ÷ √(タグの数)（タグが多い候補が有利になりすぎないようにするため）
4. **次の質問は、いまの上位候補の点差がいちばん大きく開く質問を選ぶ**

4番目がアキネーター的なところで、「答えを聞いたときにいちばん情報が増える質問」を
毎回えらび直しています。だから食べもの寄りの人には食べものを絞る質問が、
体験寄りの人には出かけ先の質問が飛んでくる、という動きになります。

9問を過ぎた時点で1位と2位が十分離れていたら、そこで打ち切ります（最大13問）。

### 迷った跡

「何を選んだか」より「何を見送ったか・どこで迷ったか」のほうが参考になることがあります。
そこで、押したものを順にそのまま記録しています。

```
0秒  はじめた
12秒 答えた：誕生日は、どんなふうに過ごせたら嬉しいですか？ → おうちでゆっくり
25秒 もどった：おうちでゆっくり を取り消した
31秒 答えた：誕生日は、どんなふうに過ごせたら嬉しいですか？ → どこかへ出かけたい
 …
2分3秒 候補が出た：ロボット掃除機、マッサージクッション、上質なストール
2分18秒 ほかの候補を見た：ロボット掃除機、マッサージクッション を見送った
2分30秒 えらんだ：上質なストール
2分41秒 決まった：シルクのスカーフ
```

記録するのは、はじめた・答えた・もどった・候補が出た・ほかの候補を見た・えらんだ・
細かく答えた・深掘りをもどった・選びなおした・最初からやりなおした・
ひとことを書いた・決まった、の12種類です。

息子が受け取る画面では時系列で並び、**もどったところと見送った候補には色をつけて**
目立たせています。スプレッドシートの「迷った跡」列にも同じものが入ります。

上限は60件です。それを超えたら記録を止めて、その旨を最後に1行残します。

### 深掘り（第2段階）

ここまでで分かるのは「果物が好きらしい」「大きな家電が要るらしい」という大分類までです。
そこから先は、**選んだ品ごとに用意した専用の質問**を1〜2問だけ出して、具体的な品まで絞ります。

```
果物  →「どの果物が好き？」→ 桃 →「やわらかい白桃 / かたい黄桃」→ 旬のやわらかい白桃
大きな家電 →「どれが助かる？」→ 洗濯機 →「縦型 / ドラム式」→ ドラム式洗濯乾燥機
```

51件のプレゼントすべてに深掘りがついていて、最終的に **203通りの具体的な品**にたどり着きます。
深掘りの答えも、押すたびにそのつど送られます。

### 送信のしかた

送り先は、使える順に自動で決まります。

1. Claude の Artifact 上で開いたときは、その `db`（動作確認用）
2. `assets/config.js` の `REPORT_ENDPOINT`（本番はこちら）
3. どちらも無ければ、最後に本人が「LINEで送る」を押す方式

毎回「その時点の回答ぜんぶ」を送っています。順番が前後して届いても、
最後の1通さえ正しければ結果が合うようにするためです。
送信中にもう一度押された分は、最新のものだけ残してまとめます。
電波が切れていたら、次に押したときにまとめて送り直します。

### 金額について

プレゼント候補に価格の情報は持たせていません。予算をたずねる質問も置いていません。
結果画面にも、息子に届く内容にも、スプレッドシートにも、金額は一切出ません。
何を贈るかは、届いた答えを見てこちら側で決める、という作りです。

### 内容を変えるには

`assets/data.js` だけ触れば変えられます。

```js
// プレゼントを足す
{ id: 'my_gift', emoji: '🎁', name: '贈りたいもの',
  note: '結果画面に出る説明文',
  tags: ['food', 'consumable', 'home'] },

// 質問を足す
{ id: 'q_new', text: '聞きたいこと',
  choices: [
    { emoji: '🅰️', label: '選択肢A', tags: { food: 3, keepsake: -2 } },
    { emoji: '🅱️', label: '選択肢B', tags: { experience: 3 } }
  ] },
```

深掘りは `REFINEMENTS` に、プレゼントの id をキーにして書きます。

```js
my_gift: { question: 'どれがいちばん？', choices: [
  // name と note があれば、そこで確定
  { emoji: '🅰️', label: '選択肢A', name: '具体的な品の名前', note: '説明' },
  // next があれば、もう一段たずねる
  { emoji: '🅱️', label: '選択肢B', next: { question: 'さらに聞くこと', choices: [ ... ] } }
]},
```

書き足したら `node test/data.test.mjs` を走らせてください。
点が入らないタグ、説明の書き忘れ、結論が大分類と同じ名前になっている、
といったよくある間違いを見つけてくれます。

タグは新しく作っても構いません。結果画面に日本語で出したいときは、
`data.js` の先頭の `TAG_LABELS` に追加してください。

## プライバシー

- 送り先は、自分で設定したスプレッドシートだけです
- 途中まで答えた内容は端末の `localStorage` にも保存され、「前回のつづきから」で再開できます
- 「押すたびに、押した順にそのまま息子に届く」ことは、最初の画面に書いてあります
  （もどった跡が残ることも含めて、黙って送ってはいません）

## 動作確認

4通りの回答パターン（お菓子派・体験派・実用家電派・家族派）で最後まで答えてみて、
妥当な候補が出ること・押すたびに自動送信されること・送信先が未設定なら手動送信に
戻ることを確かめるテストがあります。

```bash
npm install -D playwright && npx playwright install chromium   # 初回のみ
node test/e2e.mjs
```

データの整合チェックはこちら。Playwright がなくても走ります。

```bash
node test/data.test.mjs
```

受け口のほうは、敵対的なデータ（数式インジェクション、巨大な本文、壊れたJSON、
連投、行数の水増し）を投げて弾かれることを確かめます。こちらは Playwright 不要です。

```bash
node test/apps-script.test.mjs
```
